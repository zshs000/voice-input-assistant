# AI 润色模板设计

## 目标

语音识别结果通常包含口头禅、停顿、重复、语序不完整和标点缺失。润色模板负责把原始识别文本转换成更适合当前使用场景的最终文本。

原则：

- 保留原意，不编造事实。
- 删除口语噪声和无意义重复。
- 根据场景调整语气、结构和长度。
- 输出可直接复制或插入的正文。
- 原文模式必须跳过 LLM。

## 当前数据结构

```ts
type PromptTemplate = {
  id: string;
  name: string;
  description: string;
  category: "builtin" | "custom";
  enabled: boolean;
  usesLlm: boolean;
  systemPrompt: string;
  userPromptTemplate: string;
};
```

自定义模板必须包含 `{{input}}` 占位符。渲染时会用识别文本替换该占位符。

## 通用系统提示词

内置润色模板共用基础 system prompt：

```text
你是一个中文语音输入文本优化助手。你的任务是将语音识别得到的中文文本整理成更适合用户当前场景的最终文本。

要求：
1. 保留用户原意，不添加不存在的信息。
2. 可以删除口头禅、无意义重复和明显语音识别噪声。
3. 可以修正明显错别字、语病和标点问题。
4. 不要解释你的修改过程。
5. 只输出最终文本，不要输出标题、说明、引号或 Markdown，除非模板明确要求条目格式。
```

## 内置模板

### 原文模式

- `id`: `original`
- `usesLlm`: `false`
- 行为：不调用 LLM，直接输出识别文本。

### 去除口语

- `id`: `clean`
- 用途：轻量清理口头禅、重复和明显语病，尽量保持原句。
- 适用：日常输入、写作草稿、简单办公文本。

### 正式表达

- `id`: `formal`
- 用途：改写为正式、清晰、适合书面表达的中文。
- 适用：邮件、报告、作业、项目说明。

### 简洁表达

- `id`: `concise`
- 用途：压缩冗余内容，保留核心意思。
- 适用：待办、短消息、说明文字。

### 聊天表达

- `id`: `chat`
- 用途：改写为自然、轻松、适合聊天发送的中文。
- 适用：微信、QQ、社交平台、非正式沟通。

### 会议/课堂要点

- `id`: `meeting`
- 用途：将较长语音整理为清晰条目。
- 适用：会议记录、课堂笔记、讨论总结、任务梳理。

## 自定义模板

自定义模板由用户在设置弹窗中维护。当前提供三个示例入口：

- 小红书笔记
- 邮件回复
- 周报要点

保存校验：

- 模板名称不能为空。
- 提示词必须包含 `{{input}}`。
- 仅启用且合法的自定义模板会进入模板选择列表。

推荐写法：

```text
请将下面这段口语化中文改写为正式礼貌的中文邮件正文。

要求：
1. 直接给出正文段落，不要包含主题行、问候语或落款。
2. 语气专业、客观、礼貌，避免口语词。
3. 句式简洁清晰，必要时分段。
4. 保留原意，不要编造没有提到的承诺或细节。

原文：
{{input}}
```

## LLM 请求

当前使用 OpenAI-compatible Chat Completions：

```json
{
  "model": "gpt-4o-mini",
  "temperature": 0.3,
  "stream": false,
  "messages": [
    { "role": "system", "content": "..." },
    { "role": "user", "content": "..." }
  ]
}
```

接口地址由用户配置的 Base URL 拼接：

```text
{baseUrl}/chat/completions
```

## 失败兜底

- LLM 未配置：提示用户，并使用原始识别文本。
- LLM 请求失败：提示错误，并使用原始识别文本。
- LLM 返回空内容：抛出错误，由上层保留原始识别文本。
- 自定义模板无 `{{input}}`：保存时拒绝。

## 输出约束

模板应约束模型：

- 不解释修改过程。
- 不额外添加引号。
- 不输出“以下是润色结果”。
- 不编造没有说过的信息。
- 不改变用户观点。
- 除会议/课堂要点等场景外，不默认输出 Markdown。
