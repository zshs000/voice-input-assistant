# AI 润色模板设计

## 1. 设计目标

AI 润色是语音输入助手的核心亮点。语音识别只能把声音转换成文字，但用户通过语音输入时，内容通常会带有口语词、重复表达、停顿和语序不完整的问题。

润色模板的目标是让用户可以根据当前场景，把原始语音识别文本转换成更适合直接使用的文本。

设计原则：

- 保留原意，不编造新信息
- 优先修正口语化、重复和语病
- 根据场景调整语气和结构
- 输出结果简洁、可直接粘贴使用
- 用户可以关闭 AI 润色，直接使用原文

## 2. 模板处理流程

完整流程如下：

```text
原始识别文本
  -> 用户选择模板
  -> 拼接系统提示词和用户提示词
  -> 调用 OpenAI-compatible LLM
  -> 得到润色结果
  -> 输出到剪贴板或当前光标位置
```

如果用户选择“原文模式”，则跳过 LLM：

```text
原始识别文本 -> 最终输出文本
```

## 3. 通用系统提示词

所有润色模板默认使用同一段基础系统提示词，再叠加具体模板规则。

```text
你是一个中文语音输入文本优化助手。你的任务是将语音识别得到的中文文本整理成更适合用户当前场景的最终文本。

要求：
1. 保留用户原意，不添加不存在的信息。
2. 可以删除口头禅、无意义重复和明显语音识别噪声。
3. 可以修正明显错别字、语病和标点问题。
4. 不要解释你的修改过程。
5. 只输出最终文本，不要输出标题、说明、引号或 Markdown，除非模板明确要求条目格式。
```

## 4. 内置模板

### 4.1 原文模式

用途：用户不希望 AI 改写，只需要语音识别结果。

处理方式：不调用 LLM，直接输出原始识别文本。

适用场景：

- 用户希望完全保留原始表达
- 网络不可用或 LLM 未配置
- 对延迟要求更高的快速输入

### 4.2 去除口语

用途：清理语音输入中的口头禅、重复词和停顿词，尽量保持原句表达。

适用场景：

- 日常输入
- 写作草稿
- 简单办公文本

模板规则：

```text
请将下面这段语音识别文本进行轻量清理：

规则：
1. 删除口头禅，例如“嗯”“啊”“那个”“就是说”“然后然后”等。
2. 删除无意义重复。
3. 修正明显的标点和语病。
4. 尽量保持原来的句式和语气。
5. 不要大幅改写，不要扩写。

原文：
{{input}}
```

示例：

输入：

```text
嗯那个我觉得这个功能就是就是可以先做一个简单版本然后后面再优化
```

输出：

```text
我觉得这个功能可以先做一个简单版本，后面再优化。
```

### 4.3 正式表达

用途：将口语化内容改写为更正式、清晰的书面表达。

适用场景：

- 报告
- 邮件
- 作业
- 项目说明
- 正式沟通

模板规则：

```text
请将下面这段语音识别文本改写为正式、清晰、适合书面表达的中文：

规则：
1. 保留原意，不添加新事实。
2. 删除口语词和无意义重复。
3. 调整语序，使表达更有逻辑。
4. 语气保持客观、礼貌、正式。
5. 输出一段可直接使用的正文。

原文：
{{input}}
```

示例：

输入：

```text
我觉得这个地方可能有点问题就是用户如果没有配置密钥的话他就没办法用了
```

输出：

```text
我认为这里需要补充异常处理：当用户未配置 API Key 时，系统应给出明确提示，并提供进入设置页面的入口。
```

### 4.4 简洁表达

用途：将较长、啰嗦的口语内容压缩成简洁表达。

适用场景：

- 快速发送消息
- 记录待办
- 总结想法
- 写简短说明

模板规则：

```text
请将下面这段语音识别文本压缩为简洁、清楚的中文表达：

规则：
1. 保留核心意思。
2. 删除冗余铺垫、重复和口头禅。
3. 尽量缩短句子。
4. 不改变用户原本的判断和态度。
5. 只输出压缩后的文本。

原文：
{{input}}
```

示例：

输入：

```text
我想说的是这个功能现在其实不一定要做得特别复杂我们先保证它能跑起来然后后面再慢慢加
```

输出：

```text
这个功能先保证可用，不需要一开始做得太复杂，后续再逐步完善。
```

### 4.5 聊天表达

用途：将识别文本改写为自然、顺口的聊天语气。

适用场景：

- 微信
- QQ
- 社交平台
- 非正式沟通

模板规则：

```text
请将下面这段语音识别文本改写成自然、轻松、适合聊天发送的中文：

规则：
1. 保留原意。
2. 删除明显口头禅和重复。
3. 语气自然，不要太正式。
4. 不要使用夸张、油腻或过度热情的表达。
5. 输出可以直接发送的聊天文本。

原文：
{{input}}
```

示例：

输入：

```text
那个我现在可能要晚一点到因为这边还有一点事情没处理完
```

输出：

```text
我可能会晚一点到，这边还有点事情没处理完。
```

### 4.6 会议/课堂要点

用途：将较长语音整理为清晰条目。

适用场景：

- 会议记录
- 课堂笔记
- 讨论总结
- 任务梳理

模板规则：

```text
请将下面这段语音识别文本整理为清晰的要点：

规则：
1. 保留原文中的关键信息。
2. 删除口头禅、重复和无意义内容。
3. 使用简洁条目呈现。
4. 如果包含任务，请明确任务内容。
5. 不要添加原文没有的信息。

原文：
{{input}}
```

示例：

输入：

```text
今天主要说两个事情第一个是语音识别先做云端的第二个是润色模板要作为亮点然后设置里面要能填模型地址和密钥
```

输出：

```text
- 语音识别优先实现云端方案。
- AI 润色模板作为产品亮点。
- 设置页需要支持配置模型地址和 API Key。
```

### 4.7 自定义提示词

用途：允许用户根据自己的场景定义改写规则。

适用场景：

- 用户有固定写作风格
- 用户需要特定格式输出
- 用户需要专业领域表达

自定义模板应支持变量：

```text
{{input}}
```

用户提示词示例：

```text
请将下面的内容改写成适合小红书笔记的风格，要求自然、有条理，但不要夸张：

{{input}}
```

## 5. 模板数据结构

前端和后端可以使用统一的数据结构保存模板。

```ts
type PromptTemplate = {
  id: string;
  name: string;
  description: string;
  category: "builtin" | "custom";
  enabled: boolean;
  systemPrompt: string;
  userPromptTemplate: string;
};
```

内置模板由应用提供，用户可以选择使用。自定义模板由用户创建和编辑。

## 6. LLM 请求格式

产品优先支持 OpenAI-compatible Chat Completions 格式。

请求结构示例：

```json
{
  "model": "gpt-4o-mini",
  "temperature": 0.3,
  "messages": [
    {
      "role": "system",
      "content": "你是一个中文语音输入文本优化助手..."
    },
    {
      "role": "user",
      "content": "请将下面这段语音识别文本进行轻量清理：..."
    }
  ]
}
```

推荐参数：

- `temperature`: 0.2 到 0.4
- `max_tokens`: 根据输入长度动态设置
- `stream`: 默认 false

润色任务要求稳定、准确，不需要过高随机性，因此 temperature 不宜过高。

## 7. 输出约束

为了让结果可以直接插入到其他软件，LLM 输出需要遵守以下约束：

- 不输出解释
- 不输出“以下是润色结果”
- 不额外添加引号
- 不使用 Markdown，除非模板要求条目
- 不编造用户没有说过的信息
- 不改变用户原本观点

## 8. 异常与兜底

AI 润色失败时不能阻断语音输入流程。

兜底策略：

- LLM 未配置：提示用户配置，默认使用原始识别文本
- LLM 请求失败：保留原始识别文本作为最终文本
- LLM 返回空内容：使用原始识别文本
- 自定义模板缺少 `{{input}}`：保存时提示用户修正
- 输出明显过长：允许用户重新选择“简洁表达”模板处理

## 9. 产品展示重点

在产品演示中，AI 润色模板可以作为主要亮点展示：

1. 先展示原始语音识别文本中存在的口语化问题。
2. 再选择“去除口语”得到更干净的文本。
3. 再选择“正式表达”得到适合报告或邮件的文本。
4. 展示用户可以自定义提示词。
5. 说明模型服务采用 OpenAI-compatible 配置，方便接入不同模型。

这样可以体现产品不是简单的语音转文字，而是面向真实输入场景的语音输入效率工具。
