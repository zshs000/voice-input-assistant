# 语音输入助手产品设计

## 1. 产品定位

本产品是一款面向 Windows 桌面的语音输入助手。用户可以通过长按快捷键或点击界面按钮进行语音输入，系统将中文语音识别为文本，并可根据用户选择的场景模板调用大语言模型进行润色，最后将结果复制到剪贴板或自动插入到当前光标位置。

产品不做传统系统输入法 IME，而是以桌面辅助工具的形式实现接近输入法的使用体验。这样可以降低系统集成复杂度，同时保留语音输入、文本优化和快捷输出的核心价值。

核心目标是提高文本输入效率，让用户可以用自然口语快速生成可直接使用的中文文本。

## 2. 目标用户与使用场景

目标用户包括需要频繁输入文字的学生、办公人员、内容创作者和普通电脑用户。

典型场景包括：

- 聊天软件中快速输入中文消息
- 办公软件中输入邮件、报告、说明文字
- 写作或学习时将口头想法快速转成文本
- 会议、课堂或讨论后快速整理要点
- 将口语化表达改写成更正式、简洁或清晰的文本

## 3. 核心亮点

### 3.1 语音输入与文本优化结合

传统语音转文字通常只解决“听写”问题，输出结果容易保留口语词、重复表达和不完整句子。本产品将语音识别与 AI 场景润色结合，用户可以直接得到更适合使用场景的文本。

### 3.2 场景化 AI 润色模板

产品内置多种提示词模板，用户可以根据当前输入场景选择处理方式：

- 原文模式：不进行润色，直接输出识别文本
- 去除口语：删除“嗯、啊、那个、就是说”等口头禅和无意义重复
- 正式表达：将口语化内容改写为适合报告、邮件、作业的表达
- 简洁表达：压缩冗余内容，保留核心意思
- 聊天表达：改写为自然、轻松的日常聊天语气
- 会议/课堂要点：将内容整理为清晰条目
- 自定义提示词：用户自行编写处理规则

### 3.3 可配置输出方式

用户可以根据使用习惯选择输出方式：

- 仅复制到剪贴板
- 自动插入到当前光标位置
- 同时复制并插入

这种设计兼顾稳定性和效率。复制模式适合所有软件，自动插入模式更接近输入法体验。

### 3.4 开放式模型配置

大语言模型调用采用 OpenAI-compatible 接口格式。用户可以配置：

- Base URL
- API Key
- Model
- Temperature

产品优先实现 OpenAI-compatible 调用方式，同时在接口层预留其他模型供应商的扩展空间。

## 4. 核心功能范围

### 4.1 录音输入

支持两种录音方式：

- 长按快捷键开始录音，松开结束录音
- 点击页面按钮开始录音，再次点击结束录音

界面需要明确展示当前状态，例如“待机中”“录音中”“识别中”“润色中”“已完成”“失败”。

### 4.2 中文语音识别

产品以中文普通话识别为主。录音结束后，系统将音频数据提交给语音识别服务，得到原始识别文本。

音频只作为识别过程中的临时数据存在，不作为用户内容长期保存。识别完成后应清理临时音频数据。

### 4.3 AI 润色处理

识别完成后，系统根据用户当前选择的模板决定是否调用大语言模型：

- 如果选择原文模式，则直接输出识别文本
- 如果选择润色模板，则将识别文本和模板提示词发送给 LLM
- 如果选择自定义模板，则使用用户自定义提示词处理文本

AI 润色结果作为最终输出文本。

### 4.4 文本输出

最终文本可以复制到剪贴板，也可以自动插入当前光标位置。用户可以在设置中选择默认输出方式。

自动插入失败时，系统应保留复制结果，并提示用户可以手动粘贴，避免识别结果丢失。

### 4.5 历史记录

产品保留最近若干条输入历史，便于用户找回刚才的识别和润色结果。每条历史记录包含：

- 原始识别文本
- 最终输出文本
- 使用的润色模板
- 处理状态

历史记录不保存原始音频。

### 4.6 设置管理

设置页包含：

- 语音识别服务配置
- LLM Base URL、API Key、Model、Temperature
- 默认润色模板
- 默认输出方式
- 快捷键设置

配置保存在本地，不要求用户手动设置系统环境变量。

## 5. 产品流程

1. 用户打开应用。
2. 用户选择润色模板和输出方式。
3. 用户长按快捷键或点击按钮开始录音。
4. 用户松开快捷键或再次点击按钮结束录音。
5. 系统进行中文语音识别。
6. 系统根据模板决定是否调用 AI 润色。
7. 系统显示原始识别文本和最终输出文本。
8. 系统按用户设置复制或插入文本。
9. 本次输入结果进入历史记录。

## 6. 技术取舍

### 6.1 不做传统系统输入法

传统输入法需要接入系统 IME，开发和调试复杂度较高，且容易受 Windows 输入环境影响。本产品选择桌面助手形态，通过快捷键、剪贴板和自动插入实现接近输入法的体验，更适合快速形成可演示、可使用的产品。

### 6.2 先做非流式识别，预留流式能力

第一版采用“录音结束后识别”的方式。该方式稳定性高，服务接入简单，成本更容易控制。

实时流式识别可以带来边说边显示的体验，但需要流式音频上传、中间结果处理、文本修正和断句策略，复杂度更高。产品会在语音识别模块预留流式接口，方便后续扩展。

### 6.3 优先云端识别，预留本地识别

云端识别通常在准确度、速度和接入成本之间更容易取得平衡，适合当前产品形态。本地识别在隐私和长期成本上有优势，但需要处理模型下载、性能占用和设备差异。

产品通过语音识别 Provider 接口隔离具体服务，后续可以加入本地识别实现。

### 6.4 LLM 采用 OpenAI-compatible 接口

OpenAI-compatible 接口生态广，很多模型服务都支持类似格式。产品先实现这一种调用协议，可以兼顾开发效率和扩展性。

后续如果需要支持其他协议，可以在 LLM Provider 层新增适配器。

## 7. 页面结构

产品采用简洁的桌面工具界面，主要包含三个区域。

### 7.1 主输入区

主输入区展示当前录音按钮、录音状态和处理状态。用户可以直接点击按钮开始或结束录音。

### 7.2 文本结果区

文本结果区展示：

- 原始识别文本
- AI 润色后的最终文本
- 复制按钮
- 插入按钮
- 重新润色按钮

### 7.3 控制与设置区

控制与设置区提供：

- 润色模板选择
- 输出方式选择
- 快捷键提示
- 设置入口
- 最近历史记录

## 8. 关键状态

应用需要处理以下状态：

- Idle：待机中
- Recording：录音中
- Recognizing：语音识别中
- Polishing：AI 润色中
- Completed：处理完成
- Failed：处理失败

这些状态用于驱动界面显示、按钮可用性和错误提示。

## 9. 异常处理

需要覆盖的常见异常包括：

- 麦克风权限不可用
- 没有检测到有效语音
- 语音识别服务请求失败
- LLM API Key 未配置
- LLM 请求失败或超时
- 自动插入失败
- 网络不可用

异常处理原则是：不丢失用户已经得到的文本结果，尽量提供可继续操作的替代路径。

例如自动插入失败时，系统仍应把结果复制到剪贴板；AI 润色失败时，系统仍应保留原始识别文本。

## 10. 演示验收标准

产品演示时应能完成以下流程：

- 打开应用并看到主界面
- 选择一个 AI 润色模板
- 点击按钮或使用快捷键录音
- 结束录音后得到中文识别文本
- 启用 AI 润色并得到优化后的最终文本
- 将结果复制到剪贴板
- 将结果插入到当前光标位置
- 在历史记录中看到本次输入
- 在设置中配置 LLM 参数

## 11. 后续扩展方向

后续可以扩展：

- 实时流式识别
- 本地语音识别模型
- 更多 LLM 协议适配
- 用户自定义模板管理
- 术语词库和个人常用词
- 多语言识别
- 更丰富的快捷键和托盘控制
